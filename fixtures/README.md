# Fixtures

Every scenario follows PLAN.md section 7:

```
fixtures/<harness>/<version>/<os>/<scenario>/
  input/                 artifacts as the harness wrote them, after redaction
  expected/events.jsonl  `agenttail events` output for the main transcript
  expected/status.jsonl  status checkpoints
  meta.toml              harness, version, OS, capture method, date, description
  redaction.json         capture/redaction report (optional; generated by capture)
```

The seed corpus from tvdash now lives in the versioned layout:

| fixture | what it is |
|---|---|
| `claude-code/2.1/linux/seed-session` | a real Claude Code 2.1 session: a prompt, Bash / Read / Write calls, a generated title, a cost entry |
| `codex/0.160/linux/seed-exec` | a real `codex exec` rollout against a stand-in model |
| `codex/0.160/linux/seed-resume` | the same session after `codex exec resume`: a patch, a command, a `request_user_input` |
| `cursor/unknown/any/seed-session` | a handmade Cursor transcript in the shape seen on a real Mac (October 2026) |

They were already scrubbed of prose when copied from tvdash; `agenttail fixture redact`
then replaced their fake placeholder usernames (`dev`, `sam`) with canonical
`/home/<user>` and `/Users/<user>` paths. `expected/events.jsonl` is checked byte for
byte by `crates/agenttail-cli/tests/events.rs`; regenerate it with `agenttail events` after
an intentional input change.

A status checkpoint is one JSON object per line:

```json
{"after_line": 4, "now_offset_s": 30.0, "activity": "running_tool", "certainty": "firm", "reason": "tool_call_pending", "permission": "never", "sandbox": "danger_full_access"}
```

`after_line` counts entries read after feeding `input/session.jsonl` from the top. `now` for
that check is the checkpoint line's own timestamp plus `now_offset_s` (so a pending tool is
checked 30 s after its call). Optional `permission`, `sandbox` and `title` fields are
compared when present. `crates/agenttail/tests/status_fixtures.rs` runs every scenario.

Helpers live under `input/subagents/<agent>.jsonl` with optional
`input/subagents/<agent>.meta.json`. A checkpoint can feed them, in order, before it checks:

```json
{"after_line": 4, "helper": "agent-a1", "helper_line": 1, "activity": "background_work"}
{"after_line": 4, "meta": "agent-a1", "activity": "done"}
```

`helper_line` is how many lines of that helper have been fed so far (default: all). The
helper id is `subagents/<agent>.jsonl`, matching a parent `outputFile` of the same name.

## Redact, capture and scan

```sh
# Rewrite one transcript (or a directory tree) with deterministic placeholders.
agenttail fixture redact session.jsonl session.redacted.jsonl --report report.json
agenttail fixture redact --lorem --in-place fixtures/some/scenario/input

# Pick a local session (newest by default), copy its transcript and helpers, redact, show
# the value-free diff/report, and write the fixture directory. No network is used.
agenttail fixture capture --session <path-or-id> --scenario plain-qa --out fixtures

# Used by the pre-commit hook and CI: fail on any secret or real home path under fixtures/.
agenttail fixture scan fixtures
```

`redact` keeps JSON object field order (serde_json's `preserve_order`) and array order, and
keeps the line count. Each line's before/after byte span is in the report so event offsets
can be remapped. Replacements are stable and value-free: home paths and usernames become
`<user>`, emails `<email>`, hosts `<host>`, path-valued object keys `<path-NNNN>`, and
secrets `<secret-NNNN>` (the same value gets the same placeholder). Secret detection uses
both known token patterns and Shannon entropy; token-usage look-alikes such as
`input_tokens` and `token_count` are deliberately not treated as secrets. `--lorem`
replaces prose with lorem of the same character length, preserving whitespace.

The report records counts, findings by line/kind/placeholder, and an offset remap. It never
records the original secret or home path, so it can be committed with the fixture.

To enable the repository hook:

```sh
git config core.hooksPath .githooks
```

The hook scans only when a commit stages a file under `fixtures/`; CI runs the same scan on
every change to `fixtures/**` or the CLI. Nightly harness capture also runs the CLI redactor
through `AGENTTAIL_BIN` before its PR is opened.

`fixtures/cursor/handmade/vscdb-reader/` is a `state.vscdb` fixture, not a transcript
scenario: `input/state-vscdb.jsonl` holds synthetic `cursorDiskKV` key/value rows, and
`crates/agenttail/src/sqlite.rs` builds a real SQLite database from it (with the rows left in
the WAL) to test the snapshot reader.
