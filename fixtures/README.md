# Fixtures

Every scenario follows this layout:

```
fixtures/<harness>/<version>/<os>/<scenario>/
  input/                 artifacts as the harness wrote them, after redaction
  expected/events.jsonl  `agent-tail events` output for the main transcript
  expected/status.jsonl  status checkpoints
  meta.toml              harness, version, OS, capture method, date, description
  redaction.json         capture/redaction report (optional; generated by capture)
```

The Claude Desktop fixtures are **handmade** from the public Claude Agent SDK record shape,
not captured from an install; the matrix therefore says `ported-unverified`.
Desktop's `local_<id>.json` sidecar is read by the tracker, but fixture status checkpoints
exercise the audit transcript only.

The seed recordings were scrubbed before import; `agent-tail fixture redact` then replaced
their fake placeholder usernames (`dev`, `sam`) with canonical `/home/<user>` and
`/Users/<user>` paths. `expected/events.jsonl` is checked byte for
byte by `crates/agent-tail-cli/tests/events.rs`; regenerate it with `agent-tail events` after
an intentional input change. The command also accepts the scenario or `input/` directory and
writes canonical JSON (sorted keys) for the conformance runner.

A status checkpoint is one JSON object per line:

```json
{"after_line": 4, "now_offset_s": 30.0, "activity": "running_tool", "certainty": "firm", "reason": "tool_call_pending", "permission": "never", "sandbox": "danger_full_access"}
```

`after_line` counts entries read after feeding `input/session.jsonl` from the top. `now` for
that check is the checkpoint line's own timestamp plus `now_offset_s` (so a pending tool is
checked 30 s after its call). Optional `permission`, `sandbox`, `title`, `error`, `cost_usd`,
`out_tokens`, `usage`, `recent` and `background` fields are compared when present. `crates/agent-tail/tests/status_fixtures.rs`
runs every scenario, and `agent-tail status <input-dir> --checkpoints <file>` runs the same
file as the language-neutral conformance command (canonical JSON; see
[docs/conformance.md](../docs/conformance.md)).

Helpers live under `input/subagents/<agent>.jsonl` with optional
`input/subagents/<agent>.meta.json` for harnesses that write helper files. GitHub Copilot
CLI instead interleaves helper records into the main `input/session.jsonl` with a top-level
`agentId`; those are fed as part of that transcript, so that fixture has no `input/subagents`
directory. A checkpoint can feed file helpers, in order, before it checks:

```json
{"after_line": 4, "helper": "agent-a1", "helper_line": 1, "activity": "background_work"}
{"after_line": 4, "meta": "agent-a1", "activity": "done"}
```

`helper_line` is how many lines of that helper have been fed so far (default: all). The
helper id is `subagents/<agent>.jsonl`, matching a parent `outputFile` of the same name.

## Redact, capture and scan

```sh
# Rewrite one transcript (or a directory tree) with deterministic placeholders.
agent-tail fixture redact session.jsonl session.redacted.jsonl --report report.json
agent-tail fixture redact --lorem --in-place fixtures/some/scenario/input

# Pick a local session (newest by default), copy its transcript and helpers, redact, show
# the value-free diff/report, and write the fixture directory. No network is used.
agent-tail fixture capture --session <path-or-id> --scenario plain-qa --out fixtures

# Used by the pre-commit hook and CI: fail on any secret or real home path under fixtures/.
agent-tail fixture scan fixtures
```

`redact` keeps JSON object field order (serde_json's `preserve_order`) and array order, and
keeps the line count. Each line's before/after byte span is in the report so event offsets
can be remapped. Replacements are stable and value-free: home paths and usernames become
`<user>`, emails `<email>`, hosts `<host>`, path-valued object keys `<path-NNNN>`, and
secrets `<secret-NNNN>` (the same value gets the same placeholder). Secret detection uses
both known token patterns and Shannon entropy; token-usage look-alikes such as
`input_tokens` and `token_count` are deliberately not treated as secrets. `--lorem`
replaces prose with lorem of the same character length, preserving whitespace.

The report records counts, findings by line/kind/placeholder, and an offset remap. It never
records the original secret or home path, so it can be committed with the fixture.

To enable the repository hook:

```sh
git config core.hooksPath .githooks
```

The hook scans only when a commit stages a file under `fixtures/`; CI runs the same scan on
every change to `fixtures/**` or the CLI. Nightly harness capture also runs the CLI redactor
through `AGENT_TAIL_BIN` before its PR is opened.

`fixtures/cursor/handmade/vscdb-reader/` is a `state.vscdb` fixture, not a transcript
scenario: `input/state-vscdb.jsonl` holds synthetic `cursorDiskKV` key/value rows, and
`crates/agent-tail/src/sqlite.rs` builds a real SQLite database from it (with the rows left in
the WAL) to test the snapshot reader. It includes waiting, approved and denied tool-decision
shapes derived from the Cursor 3.27 IDE source (`additionalData.status: pending` for the wait),
plus the public `userDecision: pending` shape; it is not a live capture.

OpenCode's fixtures are **database row exports**, not transcript lines. Each line is
`{"table": "session" | "message" | "part", "row": {…columns…}}`, in the reader's feed order:
the session row, then each message row followed by its parts. The adapter,
`parse_lines(Harness::OpenCode, …)` and the harness driver all consume the same shape. See
[`docs/formats/opencode.md`](../docs/formats/opencode.md).
